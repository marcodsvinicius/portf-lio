Project in one minute

The problem
Interface inconsistencies and scattered references made it harder to establish a shared foundation for the new product.
My contribution
Interface audit, token definition, documentation and alignment between design and engineering.
The deliverable
A foundation of styles and components, with shared naming conventions and documentation in Notion.

03

The challenge

While a cryptocurrency product was being developed, I identified interface inconsistencies and an opportunity to establish a design system from the ground up.

I aligned the initiative with developers, the product owner and UX leadership. The aim was to organize shared references and improve technical communication, building on existing design guides and code.

04

Design decisions

Audit and reuse before defining

Why this decision
Style guides and elements reused by engineering already existed.
How I applied it
I mapped colors, typography, spacing, buttons and modals, using these references to inform the new product’s foundation.

Establish a token language

Why this decision
Design and development needed to identify the purpose of each visual choice.
How I applied it
I defined semantic variables and shared naming rules such as “brand-primary-color”. I reviewed the palette in light and dark themes, including visibility issues with yellow.

Document and maintain alignment

Why this decision
Current and future collaborators needed access to the definitions.
How I applied it
I organized documentation in Notion and held recurring discussions with designers and developers about the system’s evolution.
05

The solution

06

Deliverables and evidence

Organized visual foundation

The work brought together interface references and rules for building consistent components.

Shared language

Token naming made the purpose of visual choices explicit in discussions between design and engineering.

Team documentation

Notion provided a common place to consult the system’s definitions.

This case presents the structure and working materials created. Speed and adoption gains require additional evidence before they can be quantified.

07

Lessons learned

Governance is part of the system

Documentation and recurring engineering discussions accompanied component development.

Accessibility in visual definitions

Reviewing colors across both themes brought visibility issues into foundation discussions.

Documentation as a deliverable

The shared reference needed to remain accessible and evolve alongside the product.
